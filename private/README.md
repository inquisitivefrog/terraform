# private

A private cloud on this laptop: Docker Desktop plus [kind](https://kind.sigs.k8s.io/)
(Kubernetes in Docker). Nothing is billed, so designs too big for the AWS
Free plan are built here first.

What stands in for what:

| Private cloud (here) | Real private cloud | AWS equivalent |
|---|---|---|
| Docker Desktop VM | the data center's hardware | a region |
| kind worker node, labelled `topology.kubernetes.io/zone=dc1-a` etc. | one zone: its own power, cooling, network feeds | an Availability Zone |
| `docker stop <node>` | losing a zone | an AZ outage |
| kind's local-path volumes (one node each) | local or SAN disks in that zone | EBS (one AZ each) |
| Operators (CloudNativePG, Percona) | the DBaaS control plane | RDS / Aurora |
| Local Terraform state | a shared backend (MinIO S3, Consul, `pg`) | S3 state bucket |

Rules every tree here follows:

- Each kind cluster writes its own kubeconfig (`~/.kube/kind-<name>`), and
  Terraform and the scripts always name the context, so `~/.kube/config` and
  its current context (grid-meter's included) are never changed.
- API servers listen on 127.0.0.1 only.
- Passwords are generated by the operators into Kubernetes Secrets, never
  put in Terraform state or printed.

Prerequisites: **at least 40 GB free on the Mac's disk**; Docker Desktop
running with **12-14 GB memory and 8 CPUs** (Settings > Resources); `kind`,
`kubectl`, `helm`, `terraform` (all from Homebrew). Run long tests under
`caffeinate -i` so the laptop doesn't sleep. What a laptop can and can't
test: `datastore-clusters/docs/RUNBOOKS.md`.
